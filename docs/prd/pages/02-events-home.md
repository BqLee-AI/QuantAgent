# 02. 高价值事件首页

## 页面定位

高价值事件首页不是系统总首页，而是从 Dashboard 进入后的事件中心页面。它不是普通新闻流，也不是运行时运维页，而是一个帮助用户快速发现“今天最值得看哪些事件”的分析入口页。

页面主对象是**事件**。

## 页面目标

- 让用户在 Dashboard 之外进入更完整的事件浏览与筛选。
- 让用户在同一页完成“重点发现”和“全量浏览”。
- 为用户提供初筛依据：评分、可信度、行业影响、是否已有 AI 分析。
- 把用户稳定地送入事件详情 / 决策页。

## 核心产品判断

- 首页优先级高于插件、运行态和设置页。
- 首页要先服务操盘者判断“看哪条”，再服务技术同学看系统状态。
- 首页不直接做高风险操作。
- 首页的价值不在于“展示所有事件”，而在于“压缩操盘者的注意力成本”。

## 入口与出口

### 入口

- 从 Dashboard 点击“进入事件中心”
- 顶部导航点击“事件”
- 审批、详情、运行页中的“返回事件中心”

### 出口

- 点击事件卡片 -> 进入 `/events/:eventId`
- 点击筛选项 -> 留在本页刷新结果
- 点击“查看全部重点事件” -> 留在本页切换筛选条件

## 页面布局

建议采用上下结构：

```text
页面头
  -> 顶部状态带（可选）
  -> 今日重点事件区
  -> 筛选与排序栏
  -> 全部事件列表
```

不建议首页首版使用复杂三栏布局，否则会稀释重点事件区的主导地位。

## 页面模块

| 模块 | 页面作用 | 是否 P0 必须 | 推荐前端模块 |
| --- | --- | --- | --- |
| 页面头 | 解释本页用途和时间上下文 | 是 | `features/events/components/EventsPageHeader` |
| 顶部统计条 | 显示新事件数、重点事件数、待处理高价值事件数 | 是 | `features/events/components/EventSummaryBar` |
| 今日重点事件区 | 首屏突出最值得关注的事件 | 是 | `features/events/components/FeaturedEventDeck` |
| 筛选与排序栏 | 帮用户收窄范围 | 是 | `features/events/components/EventFilterBar` |
| 全部事件列表 | 浏览更多事件 | 是 | `features/events/components/EventList` |
| 系统提醒条 | 提示来源异常、分析失败或实时断连 | 否 | `shared/realtime/ConnectionNotice` |

## 模块详细要求

### 1. 页面头

需要展示：

- 标题：`高价值事件`
- 副标题：说明这是操盘入口，而不是普通事件归档
- 当前时间上下文，例如“最近 24 小时”

示例文案：

```text
高价值事件
优先查看最可能影响行业与标的判断的事件，再进入分析与审批。
```

### 2. 顶部统计条

建议展示 3 个核心统计：

| 指标 | 作用 |
| --- | --- |
| 新事件数 | 告诉用户今天有多少增量 |
| 今日重点事件数 | 告诉用户当前值得优先看的事件规模 |
| 待处理高价值事件数 | 告诉用户还有多少重点事件尚未进入完整判断 |

示例：

```text
新事件 24
重点事件 5
待处理重点事件 3
```

### 3. 今日重点事件区

这是事件中心最核心的模块，但在产品结构上它承接的是 Dashboard 的重点事件逻辑延展。

#### 功能目标

- 默认显示 5 条重点事件
- 支持配置显示条数
- 通过更高视觉权重突出重点事件
- 不要求显示全部详情，但必须足以让用户决定是否点入

#### 每条重点事件卡片字段

| 字段 | 必须 | 说明 |
| --- | --- | --- |
| 事件标题/摘要 | 是 | 用一句话告诉用户发生了什么 |
| 来源 | 是 | 如 Reuters、SEC、Samsung Newsroom |
| 时间 | 是 | 发布时间或采集时间 |
| 事件综合优先级评分 | 是 | 例如 `84/100` |
| 优先级等级 | 是 | 如 `S`、`A` |
| 事件可信度 | 是 | 如 `高可信` |
| 行业影响强度 | 建议 | 如 `强` |
| 时效性 | 建议 | 如 `高` |
| 涉及行业 | 是 | 如 `原油 / 油服` |
| 是否已有 AI 分析 | 是 | 如 `已分析` / `待分析` |
| 重点原因摘要 | 建议 | 如 `高可信 + 强行业冲击 + 时效高` |

#### 卡片动作

- 主动作：`查看分析`
- 次动作：`标记稍后处理`

#### 视觉建议

- 重点卡应明显大于普通列表行
- 评分与可信度不要只用颜色，必须有文本
- 行业标签要支持 1 到 3 个标签

### 4. 筛选与排序栏

#### 必要筛选

| 条件 | 类型 | 默认值 |
| --- | --- | --- |
| 时间范围 | 下拉 / 快捷按钮 | 最近 24 小时 |
| 行业 | 多选 | 全部 |
| 可信度区间 | 单选 | 全部 |
| 是否已有 AI 分析 | 单选 | 全部 |

#### 排序

首页默认排序：`最新 + 高分混合`

可选排序：

- 最新优先
- 评分优先
- 可信度优先

#### URL 规则

这些筛选条件应该进入 URL search params，便于分享和刷新恢复。

### 5. 全部事件列表

这是重点事件区之外的补充浏览区。

#### 每条列表项字段

| 字段 | 必须 | 说明 |
| --- | --- | --- |
| 标题/摘要 | 是 | 事件一句话摘要 |
| 来源 | 是 | 来源站点或账号 |
| 时间 | 是 | 发布时间 |
| 评分 | 是 | 数值分 |
| 可信度 | 是 | 用户可读等级 |
| 涉及行业 | 是 | 行业标签 |
| AI 分析状态 | 是 | 已分析 / 分析中 / 待分析 / 失败 |

#### 行操作

- 点击整行进入详情
- 悬停可显示更完整摘要

### 6. 系统提醒条

这个模块不是首页主角，但很有价值。

建议在页面顶部或筛选栏上方放一条轻量提醒：

- 实时连接已断开，当前结果可能非最新
- 某关键来源插件故障
- 某批重点事件分析失败

## 评分与重点事件关系

首页需要消费独立的评分规则，但本页必须清楚展示以下语义：

- `事件综合优先级评分`：表示这条事件整体值得优先关注的程度
- `事件可信度`：表示这条事件信息可靠度
- `行业影响强度`：表示这条事件对行业和标的影响有多强
- `时效性`：表示这条事件现在是否值得立刻处理
- `重点事件`：表示在当前时间窗内优先需要人工关注的事件

这三个概念不能混为一谈。

## 页面状态设计

| 状态 | 页面行为 |
| --- | --- |
| 初始加载 | 先渲染页面框架，再逐块展示 skeleton |
| 无重点事件 | 重点事件区显示“当前没有高价值事件” |
| 无列表结果 | 显示筛选导致无结果的空态 |
| 分析中 | 在事件卡上显示分析中状态 |
| 加载失败 | 单独显示模块级错误和重试 |
| 实时断连 | 顶部轻量提醒，不强制阻断浏览 |

## 示例

### 示例 1：石油制裁事件

重点事件区第一条显示：

```text
路透：美国考虑收紧对伊朗石油出口限制
来源：Reuters
时间：09:14
综合优先级：88 / 100
等级：S
事件可信度：高可信
行业影响强度：强
时效性：高
行业：原油、航运、油服
分析状态：已分析
重点原因：高可信 + 强行业冲击 + 时效高
```

用户点击后进入事件详情。

### 示例 2：论文类事件

某半导体论文事件综合优先级 71，可信度中等，分析状态为待分析。

首页展示时要让用户知道：

- 这条值得关注
- 但不如官方公告类事件优先级高

## 推荐前端模块拆分

- `EventsPageHeader`
- `EventSummaryBar`
- `FeaturedEventDeck`
- `FeaturedEventCard`
- `EventFilterBar`
- `EventList`
- `EventListRow`
- `EventStatusBadge`
- `EventPriorityBadge`
- `EventReliabilityBadge`
- `EventImpactStrengthBadge`

## 对应数据建议

前端在本页至少需要消费以下字段：

```ts
type EventListItem = {
  id: string
  title: string
  summary: string
  sourceName: string
  publishedAt: string
  priorityScore: number
  priorityLevel: 'S' | 'A' | 'B' | 'C'
  reliabilityScore?: number
  reliabilityLevel: 'high' | 'medium' | 'low'
  impactStrengthLevel?: 'weak' | 'medium' | 'strong' | 'very_strong'
  freshnessLevel?: 'high' | 'medium' | 'low'
  industries: string[]
  analysisStatus: 'pending' | 'running' | 'completed' | 'failed'
  featuredReason?: string
}
```

## 非目标

- 不做新闻全文阅读器
- 不做多候选动作比较
- 不做首页内联审批
- 不做全局系统调试台
