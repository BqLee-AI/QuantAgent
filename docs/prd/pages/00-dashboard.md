# 00. Dashboard 首页

## 页面定位

Dashboard 是 QuantAgent Web 的真正首页。根据 issue `#127` 评论，首页必须保留独立 dashboard，因为首页需要容纳较多核心信息，不能直接让 `/events` 既承担事件中心又承担总控首页。

Dashboard 的角色不是“什么都放一点”的仪表盘，而是操盘者每天打开系统后的第一判断面板。

## 页面目标

- 让操盘者快速看到今天最值得关注的事件。
- 让操盘者知道当前是否有待处理审批。
- 让操盘者知道系统是否存在会影响决策质量的健康问题。
- 把用户自然导入 `/events`、`/approvals`、`/runtime`。

## 页面主对象

Dashboard 不是单一对象页，但它的绝对焦点仍应是**高价值事件**。

## 入口与出口

### 入口

- 登录成功后默认进入
- 顶部品牌点击返回

### 出口

- 进入 `/events`
- 进入 `/events/:eventId`
- 进入 `/approvals`
- 进入 `/runtime`

## 页面布局

建议采用：

```text
页面头
  -> 核心指标条
  -> 今日重点事件区
  -> 下方双列：待审批区 / 系统健康提醒区
  -> 快捷入口区
```

## 页面模块

| 模块 | 作用 | 推荐前端模块 |
| --- | --- | --- |
| 页面头 | 定义首页角色和当前工作上下文 | `features/dashboard/components/DashboardHeader` |
| 核心指标条 | 展示今天的工作压力 | `features/dashboard/components/DashboardKpiBar` |
| 今日重点事件区 | 首页核心区域 | `features/dashboard/components/FeaturedEventDeck` |
| 待处理审批区 | 展示高优先级审批摘要 | `features/dashboard/components/PendingApprovalPanel` |
| 系统健康提醒区 | 首页承接系统异常提醒 | `features/dashboard/components/SystemHealthPanel` |
| 快捷入口区 | 跳转主工作页 | `features/dashboard/components/WorkEntryPanel` |

## 模块详细要求

### 1. 页面头

展示：

- 标题：`Dashboard`
- 副标题：`今天先看重点事件，再处理待审批建议`
- 当前时间范围

### 2. 核心指标条

建议展示：

- 新事件数
- 高价值事件数
- 待审批数
- 系统异常数

### 3. 今日重点事件区

#### 展示要求

- 默认展示 5 条重点事件
- 每条事件至少展示以下评分维度：
  - 事件综合优先级评分
  - 事件可信度评分
  - 行业影响强度评分
  - 时效性

#### 示例

```text
路透：美国考虑收紧对伊朗石油出口限制
综合优先级：88 / 100
事件可信度：82 / 100
行业影响强度：89 / 100
时效性：高
```

### 4. 待处理审批区

展示：

- 待处理审批总数
- 推荐度最高的 3 条建议摘要
- `进入审批工作台`

### 5. 系统健康提醒区

根据 issue `#127` 评论，系统健康提醒不单独上首页外页面，而是在首页以模块方式展示。

建议展示：

- 关键来源异常
- 分析失败数
- 实时连接状态
- 关键插件异常

### 6. 快捷入口区

建议提供：

- `进入事件中心`
- `进入审批工作台`
- `查看运行看板`

## 页面状态设计

| 状态 | 页面行为 |
| --- | --- |
| 正常 | 展示完整概览 |
| 无重点事件 | 重点区显示空态 |
| 无审批 | 审批区显示“当前无待处理审批” |
| 系统异常 | 健康提醒区高亮 |

## 非目标

- 不替代 `/events` 事件中心
- 不做插件治理首页
- 不做完整调试台
