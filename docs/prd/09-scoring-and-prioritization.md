# 09. 评分体系与高价值事件判定 PRD

## 文档状态

**版本**：v1.0  
**状态**：详细产品稿  
**关联 issue**：#128  
**作用**：定义 QuantAgent V1 中与事件筛选、事件可信度、分析可信度、建议优先级和首页重点事件判定相关的评分体系

## 为什么单独立文档

QuantAgent 不是只有一种评分。

如果只用一个“总分”去概括所有判断，前端和用户都会误解系统到底在表达什么。根据 `#128` 评论，系统里至少会同时存在多种评分：

- 事件来源本身是否权威
- 事件内容是否可信
- 事件对行业和标的的潜在影响强度
- 当前建议是否值得优先人工判断

这些评分用途不同、展示位置不同、计算输入也不同，因此必须单独写成评分 PRD。

## 评分体系总原则

- 不存在一个万能分数解释所有事情。
- 前端必须区分“事件可信”和“事件重要”。
- 评分结果必须服务于用户决策，而不是只服务模型内部。
- 评分展示应为结构化分层，不能把多个概念叠成一个数字。
- 高风险建议必须允许低置信度或冲突信息存在，不能因为有建议就假装确定。

## V1 评分体系总览

| 评分名称 | 作用 | 页面主要使用位置 | 是否用户可见 |
| --- | --- | --- | --- |
| 来源权威度评分 | 判断来源本身可信程度 | Dashboard、事件首页、详情页 | 是 |
| 事件可信度评分 | 判断事件内容可信程度 | Dashboard、事件首页、详情页、审批页 | 是 |
| 行业影响强度评分 | 判断事件对行业/标的冲击程度 | Dashboard、事件首页、详情页 | 是 |
| 时效性评分 | 判断事件当前是否值得优先处理 | Dashboard、事件首页 | 是 |
| 事件综合优先级评分 | 用于重点事件排序与入选 | Dashboard、事件首页 | 是 |
| 分析置信度评分 | 判断当前分析结论是否稳定 | 详情页、审批页 | 是 |
| 建议推荐度评分 | 判断某条建议是否值得优先审批 | 详情页、审批页 | 是 |

## 一、来源权威度评分

### 定义

来源权威度评分回答的问题是：

`这条消息来自的渠道，本身靠不靠谱？`

它不是事件已经被证实，只是说明信源本身的权重。

### 典型输入

- 来源类型：官方公告 / 主流媒体 / 行业媒体 / 社交账号 / 论文 / 论坛
- 历史可靠性记录
- 是否已在系统中被标为核心来源
- 是否存在历史误报或夸大

### 示例分层

| 等级 | 示例 |
| --- | --- |
| A | 官方公告、监管文件、头部主流媒体 |
| B | 行业主流媒体、知名分析机构 |
| C | 普通媒体、二级转述 |
| D | 匿名社交账号、未经验证论坛 |

### 前端展示建议

- 用文字等级 + 短说明
- 不建议只显示一个数字

示例：

```text
来源权威度：A
说明：主流媒体首发
```

## 二、事件可信度评分

### 定义

事件可信度评分回答的问题是：

`这件事本身现在有多大概率是真的？`

它比来源权威度更进一步，因为同一个高权威来源，也可能发布尚未证实的传闻。

### 典型输入

- 来源权威度
- 是否有第二信源交叉验证
- 是否有官方确认
- 是否存在互相冲突的信息
- 是否能通过搜索工具找到近似事件或延续上下文

### 前端展示建议

建议同时给：

- 数值分，例如 `82/100`
- 用户可读等级，例如 `高可信`
- 解释标签，例如 `双信源交叉验证`

### 示例

```text
事件可信度：82 / 100
等级：高可信
原因：Reuters 首发 + 官方发言人间接确认
```

## 三、行业影响强度评分

### 定义

行业影响强度回答的是：

`就算这条事件是真的，它对行业和标的到底会造成多大冲击？`

### 典型输入

- 影响是否直达核心供需或核心政策
- 是否影响多个标的或多个行业
- 是否影响一级因果链还是二阶因果链
- 是否存在明显可映射的市场对象

### 前端展示建议

- 用数值分 + 标签
- 标签建议为：`弱 / 中 / 强 / 极强`

### 示例

```text
行业影响强度：89 / 100
等级：强
说明：直接影响原油供给预期，并影响近月期限结构
```

## 四、时效性评分

### 定义

时效性评分回答的是：

`这条事件是不是现在就该看，而不是晚点再看？`

### 典型输入

- 发布时间距现在的时间差
- 市场是否仍处于可反应窗口
- 同类事件是否已被市场充分消化
- 是否存在审批或处理时限

### 前端展示建议

- 使用 `高 / 中 / 低` 时效标签
- 可辅助显示“发布时间距今多久”

示例：

```text
时效性：高
发布时间：14 分钟前
```

## 五、事件综合优先级评分

### 定义

事件综合优先级评分用于回答：

`在所有事件里，今天操盘者该优先看哪几条？`

这个分数是 Dashboard 和首页的核心驱动分。

### 组成建议

首版至少综合以下因素：

- 来源权威度
- 事件可信度
- 行业影响强度
- 时效性

### 输出形式

- 数值分，例如 `88/100`
- 优先级等级：`S / A / B / C`

### 用途

- Dashboard 的重点事件区排序
- `/events` 首页的重点事件入选
- 待处理高价值事件统计

### 示例

```text
事件优先级：88 / 100
等级：S
入选原因：高可信 + 强影响 + 高时效
```

## 六、分析置信度评分

### 定义

分析置信度回答的是：

`系统对当前行业影响分析本身有多确定？`

这不是事件真假，而是分析结论稳定性。

### 典型输入

- 分析过程是否完整
- 关键工具调用是否成功
- 是否存在冲突观点
- 是否存在数据缺口

### 页面位置

- 事件详情页
- 审批页

### 示例

```text
分析置信度：74 / 100
说明：结论方向清晰，但缺少官方二次验证
```

## 七、建议推荐度评分

### 定义

建议推荐度回答的是：

`在当前上下文下，这条建议是否值得优先进入人工判断或审批？`

它不是自动执行分，也不是策略胜率分。

### 典型输入

- 事件综合优先级
- 分析置信度
- 风险等级
- 是否已有相似仓位暴露
- 是否满足人工审批前置条件

### 页面位置

- 事件详情页的最佳动作卡
- 审批工作台排序

### 示例

```text
建议推荐度：78 / 100
风险等级：中
说明：建议值得审批，但不代表应自动执行
```

## Dashboard / 首页如何用这些评分

### Dashboard

建议 Dashboard 重点事件卡展示：

- 事件综合优先级评分
- 事件可信度评分
- 行业影响强度评分
- 时效性标签

### `/events` 首页

`/events` 更偏浏览与筛选，因此要展示：

- 事件综合优先级评分
- 事件可信度评分
- 是否已有 AI 分析
- 涉及行业

## 详情页和审批页如何用评分

### 详情页

详情页重点展示：

- 事件可信度评分
- 分析置信度评分
- 建议推荐度评分
- 风险等级

### 审批页

审批页重点展示：

- 建议推荐度评分
- 风险等级
- 事件可信度摘要
- 分析置信度摘要

审批排序默认按建议推荐度排序，而不是按事件综合优先级排序。

## 第一版不做的评分能力

- 不做复杂个性化学习排序
- 不做账户收益回测驱动评分
- 不做自动执行放行分
- 不做“一个总分解释全部”的错误简化

## 示例：一条事件在多个评分维度下的展示

```text
事件：美国考虑收紧对伊朗石油出口限制

来源权威度：A
事件可信度：82 / 100（高可信）
行业影响强度：89 / 100（强）
时效性：高
事件综合优先级：88 / 100（S）

分析置信度：74 / 100
建议推荐度：78 / 100
风险等级：中
```

## 产品约束

- 所有评分都必须能被用户解释，不允许只有数字没有含义。
- 不允许把“来源权威度”误写成“事件可信度”。
- 不允许把“建议推荐度”误解为“真实执行建议”。
- 高分不意味着自动执行，只意味着更值得优先判断。
